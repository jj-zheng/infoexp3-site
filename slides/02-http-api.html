Method / URL / Status

HTTPは Request（依頼） と Response（結果） のやり取り。

① Request：何をしてほしい？

GET /api/messages HTTP/1.1
Host: localhost:5000

Method：GET → 投稿一覧を取得

URL：/api/messages → 対象のAPI

HTTP/1.1：通信のプロトコルバージョン

② Response：結果はどうだった？

HTTP/1.1 200 OK
Content-Type: application/json

[{"id":1,"name":"Alice",
  "message":"Hello!"}]

Status：200 OK → 取得成功

Body：投稿データ（JSON）

ほかのStatus例：201 Created（作成成功）／400 Bad Request（入力に問題）／404 Not Found（対象なし）
問い：GET /api/messages と POST /api/messages は、URLが同じなのに、なぜ処理が違う？

※ 上のHTTPメッセージとJSONは説明用の例です。実際のResponseは後のcurl実習で確認します。

Flask Routeを読む

GET：投稿一覧を取得

@app.get("/api/messages")
def get_messages():
    ...
    return jsonify(...)

GET /api/messages → get_messages()
jsonify()：PythonのデータをJSON Responseにする。

POST：新しい投稿を登録

@app.post("/api/messages")
def create_message():
    data = request.get_json(...)
    ...
    return jsonify(...), 201

POST /api/messages → create_message()
request.get_json()：Request BodyのJSONを読む。

Request → Response： request.get_json() は受信、jsonify() は送信。, 201 は作成成功のStatus Code。
確認： 先ほどの curl GET / POST は、app.py のどちらの関数に対応する？ ※コードは説明用の抜粋です。実際の処理は自分の app.py で確認。
このコードは流れを示す抜粋イメージです。実際の処理は自分の app.py で確認してください。

Frontendのfetchを読む

static/app.js の fetch() がBrowserからHTTP Requestを送る。

const response = await fetch('/api/messages', {
  method: 'POST',
  headers: {'Content-Type': 'application/json'},
  body: JSON.stringify({name, message})
});

送る側（Request）

method: 'POST'：投稿を作成
headers：JSONを送ると通知
JSON.stringify(...)：JavaScriptの値 → JSON文字列

受け取る側（Response）

response.status：結果のStatus Code
await response.json()：JSON Response BodyをJavaScriptの値に変換

問い： fetch() の POST /api/messages は app.py のどのRouteにつながる？ ※説明用コード。実際の処理は static/app.js で確認。
これは fetch() の基本形です。実際の送信処理と画面更新の順序は static/app.js で確認してください。

Requestの旅

① Browser：投稿ボタンを押す
↓
② JavaScript（static/app.js）：JSONを作り、POSTを送る
↓
③ Flask（app.py）：POST Routeで受信・入力確認・保存
↓
④ Flask → Browser：201 Created + JSON Response
↓
⑤ JavaScript：画面を更新し、投稿を表示
⑤の実装は要確認： 再度 GET /api/messages を送る場合と、POSTのResponseを利用する場合がある。自分の static/app.js で確認しよう。
⑥の再取得があるか、またはPOSTのResponseを使って更新するかは、実際のJavaScriptで確かめてください。
