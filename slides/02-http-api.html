HTTPの最小モデル

Client / Browser Server / Flask │ Request: GET /api/messages │ ├────────────────────────────────────────▶│ │ Response: 200 OK + JSON │ │◀────────────────────────────────────────┤

HTTPはClientとServerがやり取りするためのルール。

← → キーで移動

Method / URL / Status

HTTPは Request（依頼） と Response（結果） のやり取り。

① Request：何をしてほしい？

GET /api/messages HTTP/1.1
Host: localhost:5000

Method：GET → 投稿一覧を取得

URL：/api/messages → 対象のAPI

HTTP/1.1：通信のプロトコルバージョン

② Response：結果はどうだった？

HTTP/1.1 200 OK
Content-Type: application/json

[{"id":1,"name":"Alice",
  "message":"Hello!"}]

Status：200 OK → 取得成功

Body：投稿データ（JSON）

ほかのStatus例：201 Created（作成成功）／400 Bad Request（入力に問題）／404 Not Found（対象なし）
問い：GET /api/messages と POST /api/messages は、URLが同じなのに、なぜ処理が違う？

※ 上のHTTPメッセージとJSONは説明用の例です。実際のResponseは後のcurl実習で確認します。

Hands-on 2：GETとlocalhost

Codespaceの新しいTerminalで実行し、StatusとJSONを確認します。

curl -i http://localhost:5000/api/messages

Requestはどこへ？

Codespace内のcurl ↓ localhost:5000 Docker Port Mapping（5000:5000） ↓ Container :5000 Flask（app.py）

ここでのlocalhost

curlを実行しているCodespace自身を指します。

手元のPC（Macなど）やGitHub Pagesではありません。

確認：200 OK とResponse Body（例：[]）を区別する。

ポイント：localhost はコマンドを実行する環境自身。PCのTerminalで実行すると、そのPCを指します。

問い：同じコマンドを自分のPCで実行すると、同じMiniBoardにアクセスできる？

POSTをcurlで送る

curl -i -X POST http://localhost:5000/api/messages \
  -H "Content-Type: application/json" \
  -d '{"name":"api-test","message":"Hello API"}'

ResponseのStatusとJSONを確認。次にBrowserを再読み込みして投稿が見えるか確かめる。

Browserとcurlは別のClientだが、同じBackendへRequestを送っている。

Flask Routeを読む

@app.get("/api/messages")
def get_messages():
    ...
    return jsonify(...)

@app.post("/api/messages")
def create_message():
    data = request.get_json(...)
    ...
    return jsonify(...), 201

@app.get / @app.post がHTTP RequestとPython functionを結び付ける。

このコードは流れを示す抜粋イメージです。実際の処理は自分の app.py で確認してください。

Frontendのfetchを読む

await fetch('/api/messages', {
  method: 'POST',
  headers: {'Content-Type': 'application/json'},
  body: JSON.stringify({name, message})
});

JavaScriptがBrowserからHTTP Requestを送っている。

これは fetch() の基本形です。実際の送信処理と画面更新の順序は static/app.js で確認してください。

Requestの旅

① User clicks 投稿 ↓ ② JavaScript submit handler ↓ ③ POST /api/messages + JSON ↓ ④ Flask route / Python processing ↓ ⑤ HTTP Response + JSON ↓ ⑥ GET /api/messages ↓ ⑦ DOMを更新 → 投稿が見える
⑥の再取得があるか、またはPOSTのResponseを使って更新するかは、実際のJavaScriptで確かめてください。
