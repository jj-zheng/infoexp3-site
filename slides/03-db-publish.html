なぜDatabaseが必要？

アプリを終了しても、投稿したデータを残したい。

Pythonの変数だけの場合

messages = ["Hello!"]

メモリに保持するため、プロセスを終了すると通常は失われる。

SQLiteを使う場合

data/miniboard.db

DBファイルに保存し、ファイルが残っていれば再起動後も読み出せる。

ただし、Containerを削除したときにDBファイルが残るかは、保存場所によります。

SQLiteとは？

SQLiteは、SQLを使ってデータを管理する軽量なDatabase Engineです。

Flask（app.py）
↓
Python（sqlite3）
↓
SQLite
↓
data/miniboard.db

SQLiteの特徴

専用のDatabase Serverを別に起動する必要がない。

MiniBoardの保存先

DB = Path("data/miniboard.db")
SQLiteはデータを管理する仕組み、miniboard.db は保存先のファイルです。

Containerを削除すると、データはどうなる？

SQLiteのデータが残るかどうかは、DBファイルの保存場所によって変わります。

① stop → start

同じContainerを再起動する。

Container内のDBファイルは残る。

② rm → run

Containerを削除して新しく作る。

旧Container内だけにあったDBは失われる。

例外：Volume / Bind MountでContainer外に保存している場合は、削除後もデータを保持できます。

今回はContainer削除の実験はしません。

GitHub ≠ Web Service
