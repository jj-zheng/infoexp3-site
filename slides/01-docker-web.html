困ること

Pythonの版、library、OS設定などが違うと「自分の環境では動く」が起きる。

Docker

アプリと実行に必要な環境をImageとしてまとめ、同じImageからContainerを作る。

目的はDockerそのものではなく、実行環境を再現しやすくすること。
← → キーで移動

Dockerfile

Imageをどう作るかを書くbuild instructions

Image

アプリと実行環境をまとめた実行用のひな型

Container

Imageから作られた実行環境のinstance

Dockerfile ── docker build ──▶ Image ── docker run ──▶ Container

FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 5000
CMD ["python", "app.py"]

Teamで1行ずつ：「この行がないと何が困る？」まで説明してみる。

← → キーで移動
docker build -t miniboard .
Dockerfile + Source Code │ │ docker build ▼ miniboard:latest
docker images
-t miniboard はImageに名前(tag)を付ける。最後の . はbuild context。
← → キーで移動
docker run --name miniboard -p 5000:5000 miniboard
miniboard Image │ docker run ▼ miniboard Container │ └─ Flask :5000

Terminalに Running on ...:5000 が出れば起動成功。

← → キーで移動
-p 5000:5000

左：Codespace側のPort
右：Container側のPort

Browser ↓ Codespaces :5000 ↓ -p 5000:5000 Container :5000 ↓ Flask
数字は何でもよいわけではありません。右側はContainer内でアプリがlistenしているPortと一致させます。

投稿したあと Ctrl+C で停止し：

docker start -a miniboard

Browserをrefresh。投稿は残っていますか？

同じContainerをstop/startしても、Containerのfilesystemはそのまま残ります。
← → キーで移動
# Ctrl+C で停止後
docker rm miniboard
docker run --name miniboard -p 5000:5000 miniboard

もう一度Browserを開く。先ほどの投稿は？

Containerを削除して新しく作ると、Container内に作られたDBも新しくなる。
この理由は第3回でDatabaseと一緒に考えます。
