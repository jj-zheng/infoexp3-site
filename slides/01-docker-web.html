← → キーで移動

まずはシンプルなWeb ServerをContainerで動かそう。

docker run --name myweb -p 8080:80 nginx

操作：CodespacesのPortsタブで 8080 を開く（Visibilityは Private のまま）。

期待される結果：Browserに Welcome to nginx! と表示される。

確認：8080 と 80 はそれぞれ何のPort？

終了：Terminalで Ctrl+C。次の操作前に docker rm myweb。

← → キーで移動
Browser → CodespacesのPort 8080 → -p 8080:80 → nginx ContainerのPort 80

HOST_PORT : CONTAINER_PORT

-p 8080:80 は「Codespace側の8080番に来た通信を、Container内の80番へ転送する」という意味。

Codespacesでは、手元のPCの localhost:8080 ではなく、Portsタブの転送URL を開く。

次はMiniBoardでも同じ仕組みを使います。

← → キーで移動
-p 5000:5000

左：Codespace側のPort
右：Container側のPort

Browser ↓ Codespaces :5000 ↓ -p 5000:5000 Container :5000 ↓ Flask
数字は何でもよいわけではありません。右側はContainer内でアプリがlistenしているPortと一致させます。

docker ps にContainerがない？

docker run --rm hello-world では、Containerは作成・実行されますが、処理終了後に --rm により自動削除されます。

docker images → Image は残る
docker ps → 実行中のContainerだけを表示するため、hello-worldは表示されない

停止したContainerも確認してみよう

docker run hello-world
docker ps
docker ps -a

--rm を付けなければ、終了したContainerは docker ps -a で確認できます。

このあとnginxを起動すると、実行中のContainerを docker ps で確認できます。

← → キーで移動

Portsタブに複数の番号が表示されてもOK

5000 はMiniBoard、8080 はnginx実験で使うポートです。

Codespaces / VS Codeが自動的に検出した別の番号が表示されることもあります。演習に関係のないポートを削除する必要はありません。

確認すること：目的のポート番号・転送URL・Private の表示範囲。

Terminalが空白になる場合は「Codespacesガイド」のTroubleshootingを確認してください。

Containerを停止して、同じContainerを再起動する。

  1. MiniBoardに keep-test と投稿。

ソースを変えても、既存Imageは自動更新されない。

  1. 画面タイトルなど、表示される文字を1か所変更する。
  2. 実行中のContainerを Ctrl+C で停止。
  3. 旧Containerを削除し、Imageを再Buildする。
docker rm miniboard
docker build -t miniboard .
docker run --name miniboard -p 5000:5000 miniboard
期待される結果：変更した表示が反映される。

確認：なぜ変更後に docker build が必要？
