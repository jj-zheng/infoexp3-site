成績評価・出席・個人レポート

チームとして完成させたWebアプリケーションと、各自が演習で行ったこと・理解したことの両方を評価します。

評価方法

評価項目割合評価単位
最終Webアプリケーション50%チーム
各回の個人レポート50%個人
合計100%—

最終Webアプリケーション（50%）

チーム単位で評価します。基本要件を満たしているか、Webアプリケーションとして正しく動作するか、Frontend / Backend / API / Database が連携しているか、+1機能やチーム独自の工夫を含めて、最終的な完成度を総合的に評価します。

各回の個人レポート（50%）

第1回〜第3回の各回終了後に、各自で短いレポートを提出します。主に次の2点を確認します。

  1. 自分が担当・実施した作業を具体的に説明できること。
  2. その回で扱った技術や仕組みを自分の言葉で説明できること。
ポイント： レポートは作業量だけを見るものではありません。「何をしたか」と「なぜそのように動くのか」を説明できることを重視します。

第1回レポート

  1. 今日、自分が担当・実施した作業を具体的に説明してください。
  2. Docker Image と Container の違いを、自分の言葉で説明してください。
  3. 今日の演習で理解したこと、またはまだ分からないことを書いてください。

第2回レポート

  1. 今日、自分が担当・実施した作業を具体的に説明してください。
  2. MiniBoardで「投稿」してから画面に表示されるまで、Frontend、HTTP、Backendがどのように関係するか説明してください。
  3. 今日の演習で理解したこと、またはまだ分からないことを書いてください。

第3回レポート

  1. 最終Webアプリケーションの開発において、自分が担当した内容を具体的に説明してください。
  2. チームで追加した「+1機能」の仕組みを説明してください。
  3. 3回の演習を通して、Webアプリケーション開発について学んだことを説明してください。

出席について

本テーマは全3回の演習で構成されています。原則として、3回すべてに出席してください。
無断欠席が2回以上の場合は、評価対象としません。
やむを得ない事情により欠席する場合は、原則として事前に担当教員へ連絡してください。必要に応じて個別に対応します。

生成AIの利用

生成AIを利用する場合も、提出物やコードの内容を自分で確認し、説明できることが前提です。

説明できないコードは merge しない。説明できないシステムは完成とはしない。
